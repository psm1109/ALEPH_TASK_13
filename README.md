# 사이 — 우리 사이, 다음 한 곡

함께 들을 음악을 곡 신청과 한 표로 정하는 웹 앱입니다. 6자리 방 코드로 참여하고, 각 기기가 방의 현재 재생 위치부터 함께 듣습니다. 첫 곡이 들어오면 자동 재생하며, 빈 방은 자동 삭제됩니다.

## Vercel 배포

**[번호순 환경설정·배포 안내](DEPLOYMENT.md)** 를 따라 진행하세요. Vercel 계정, Upstash Redis의 REST 주소·쓰기 토큰이 필요합니다. 제목 검색을 사용하려면 YouTube Data API 키도 등록합니다. 실제 서비스 배포나 계정 생성은 이 저장소의 코드 변경만으로 수행되지 않습니다.

정적 화면은 Vercel CDN에서, API는 Node.js Vercel Function 하나에서 실행합니다. 방·접속 상태·곡·투표·검색 캐시와 검색 제한은 Upstash Redis에 공유 저장합니다. REST API를 직접 호출하므로 별도 실행 패키지가 필요 없습니다.

## 로컬 실행

Node.js 22.9 이상(배포는 22.x).

```powershell
# .env가 없을 때만 복사합니다. 기존 API 키를 덮어쓰지 마세요.
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm start
```

기본 주소는 http://localhost:3000 입니다. `.env`의 PORT로 바꿀 수 있습니다. Upstash 주소·토큰을 둘 다 비우면 개발용 단일 프로세스 파일 저장소 `data/serverless-local.json`을 사용합니다. Vercel에서는 로컬 저장소로 대체하지 않으며 DB 미설정 오류를 표시합니다. 기존 초안의 `listening-rooms.json`과 32자리 링크는 새 6자리 방으로 자동 이전하지 않습니다.

## 사용 규칙

1. 방을 만들면 6자리 숫자 코드가 발급됩니다. 같은 사이트 첫 화면의 코드 입력 또는 초대 링크로 접속하고 닉네임을 등록합니다. 코드를 아는 사람은 참여할 수 있으므로 비공개 인증 방은 아닙니다.
2. 첫 곡은 신청과 동시에 현재 곡이 됩니다. 이후 신청곡은 대기열에 들어가며, 재생 종료 시 투표를 반영해 다음 곡으로 넘어갑니다. 빈 대기 상태에 다시 곡을 넣으면 즉시 시작합니다.
3. 특정 재생 담당 기기나 방장용 재생·정지·취소 버튼은 없습니다. 모든 참여자의 브라우저에 공식 YouTube 플레이어를 표시합니다. 방이 곡을 1분 20초 재생 중이면 새 참여자도 해당 위치부터 시작합니다. 브라우저의 자동 재생 차단이 발생하면 ‘방의 현재 위치로 듣기’를 한 번 누릅니다. 동영상 자체의 기본 컨트롤은 유지합니다.
4. 서버의 곡 시작 시각을 공통 기준으로 사용하므로 방 생성자가 나가거나 새로고침해도 다른 사람의 음악은 처음으로 돌아가지 않습니다. 한 기기에서 일시 정지한 동안에도 방의 시계는 흐르며, 다시 들으면 현재 위치로 합류합니다. 재생 중 3초 이상 차이가 나면 위치를 보정합니다. 버퍼링·광고·플랫폼 동작의 차이가 있어 정밀한 동시 재생을 보장하지는 않습니다.
5. 대기곡마다 듣고 싶어요(+1) 또는 이번엔 패스(−1) 중 한 표. 같은 버튼은 취소, 반대 버튼은 교체합니다. 신청 자체는 자동 찬성표를 만들지 않습니다. 점수순·동점 등록순이며, 다른 신청자가 있으면 같은 사람의 곡이 연속되지 않도록 조정합니다.
6. 현재 곡은 현재 참여자 과반(`floor(N / 2) + 1`)의 건너뛰기 투표로 넘깁니다. 재생 오류도 과반의 기기에서 보고될 때 다음 곡으로 넘겨 한 기기의 오류가 모두의 음악을 즉시 중단하지 않게 합니다. 플랫폼 정책으로 재생되지 않는 영상이 있을 수 있습니다.
7. 브라우저는 15초마다 접속 확인을 보내며, 90초 동안 연결 확인이 없는 사람은 다른 참여자의 다음 상태 갱신 때 자동 퇴장됩니다. 명시적인 마지막 퇴장은 방을 즉시 삭제합니다. 모두 창을 닫거나 연결이 끊기면 마지막 접속 확인·작업 후 90초에 Redis가 방 데이터를 만료시킵니다. 접속 조회만 하는 미참여자는 방 수명을 늘리지 않습니다. 브라우저 절전·OS 수면으로 접속 확인이 중단돼도 같은 규칙을 적용합니다.
8. HttpOnly 쿠키로 브라우저를 식별합니다. 새로고침·닉네임 변경·반복 요청으로 표를 늘릴 수 없습니다. 다른 브라우저·시크릿 모드·쿠키 삭제·여러 기기 사용까지 막는 실제 기기 인증은 아닙니다. 퇴장 시 해당 참여자의 표도 제거됩니다.
9. 합계와 본인의 선택만 표시합니다. 다른 사람의 개별 투표·브라우저 식별값은 반환하지 않습니다. 소규모 방에서는 합계 변화로 선택을 추측할 수 있어 완전한 익명성을 보장하지는 않습니다.

## 서버리스 저장 구조

- `api/index.js`: Vercel 함수 진입점. 재생·투표 규칙은 `lib/handler.js`, 대기열과 접속 정리는 `room.js`.
- `lib/storage.js`: Upstash REST 연결과 방 단위 원자적 비교 후 저장. 방 상태·투표를 읽은 이후 다른 요청이 먼저 저장했다면 최신 상태로 다시 처리합니다. 중복 곡 종료 요청으로 두 곡이 연속 건너뛰어지지 않도록 현재 곡 ID도 확인합니다.
- `lib/storage-local.js`: 로컬 개발·테스트 전용 저장소. 파일에 기록이 남아 있어도 만료된 방은 조회할 수 없습니다. 다음 쓰기 시 만료 데이터를 정리합니다.
- 방 데이터 TTL 90초, 검색 캐시 TTL 5분, 새 검색 제한 3초. 방 만료는 Redis TTL로 처리하므로 Cron이나 계속 실행되는 서버가 필요 없습니다.
- `playback.startedAt`과 영상 길이로 공유 재생 위치·종료 시각을 계산합니다. 영상 길이는 YouTube 플레이어가 메타데이터 로드 후 처음 보고한 값을 저장하므로 추가 Data API 호출은 하지 않습니다. 서버는 조회·접속 확인·작업 요청 시 경과 시간을 정리합니다. 브라우저 종료 알림 없이도 다음 곡을 결정하며, 늦은 전환은 이전 곡 종료 시각을 이어받습니다. 길이를 아직 모르는 다음 곡은 메타데이터 로드 후 정리합니다. 상시 실행되는 음악 서버나 백그라운드 재생 작업은 아닙니다.
- 고정 길이의 녹화된 영상·음악을 대상으로 합니다. 실시간 방송은 길이가 계속 바뀌므로 지원 대상이 아닙니다. 기기의 시각 차이는 서버 응답 시각과 브라우저의 단조 시계로 보정합니다.
- Vercel Production·Preview·로컬은 기본 키 접두사가 달라 같은 DB에서도 방과 검색 캐시가 분리됩니다. 다른 앱까지 같은 DB를 공유한다면 `REDIS_KEY_PREFIX`를 별도로 지정하세요.
- 상태 조회는 화면이 보일 때 각 기기에서 5초마다, 접속 확인은 별도로 15초마다 실행합니다. 곡 변경 반영에는 조회 간격·네트워크 지연이 생기지만, 합류 위치는 경과 시간을 포함해 계산합니다. 조회에 따른 곡 전환 저장은 기존 TTL을 유지하여 미참여자의 조회가 빈 방 수명을 늘리지 않게 합니다. Vercel·Upstash 모두 무료 플랜 기준으로 사용하며 요청량을 확인하세요. 대규모 운영에는 방 접근 제어와 생성 요청 제한이 추가로 필요합니다.

## 논문과의 연결

T10 최종 논문은 공개 집계자료 330명에서 외향성과 평균 음향적 긍정성의 뚜렷한 양의 관계를 확인하지 못했습니다(r=0.065518, 95% CI −0.045077~0.180637). 성격으로 취향을 짐작하는 대신 실제 신청과 투표를 반영하는 앱으로 연결했습니다. 관계가 없다는 증명이나 앱 효과에 대한 검증 결과는 아닙니다.

## 확인

```powershell
npm test
npm run build
```

로컬 API, 분산 동시 요청, 6자리 코드, 중간 합류 위치, 시계에 따른 자동 전환, 중복 표 방지, 과반 전환, 퇴장·만료와 TTL 유지, 공유 검색 캐시, Vercel 요청 형식을 검사합니다. Redis는 REST 계약을 구현한 로컬 모형으로 검사하며 실제 Upstash와 Vercel 계정 연결·실서비스 배포 검증은 아닙니다.
