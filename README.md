# 사이 — 우리 사이, 다음 한 곡

함께 들을 음악을 곡 신청과 한 표로 정하고, 직접 남긴 감상으로 이번 모임의 취향을 돌아보는 웹 앱입니다. 6자리 방 코드로 참여하고, 방을 만든 사람의 기기에서만 음악을 재생합니다. 첫 곡이 들어오면 자동 재생하며, 진행 중인 빈 방은 자동 삭제됩니다.

## Vercel 배포

**[번호순 환경설정·배포 안내](DEPLOYMENT.md)** 를 따라 진행하세요. Vercel 계정, Upstash Redis의 REST 주소·쓰기 토큰이 필요합니다. 제목 검색과 곡 신청 검증을 위해 YouTube Data API 키도 등록합니다. 키가 없거나 검증에 실패하면 링크 신청도 차단합니다. 실제 서비스 배포나 계정 생성은 이 저장소의 코드 변경만으로 수행되지 않습니다.

정적 화면은 Vercel CDN에서, API는 Node.js Vercel Function 하나에서 실행합니다. 방·접속 상태·곡·투표·검색 캐시와 검색 제한은 Upstash Redis에 공유 저장합니다. REST API를 직접 호출하므로 별도 실행 패키지가 필요 없습니다.

## 로컬 실행

Node.js 22.9 이상(배포는 22.x).

```powershell
# .env가 없을 때만 복사합니다. 기존 API 키를 덮어쓰지 마세요.
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm start
```

기본 주소는 http://localhost:3000 입니다. `.env`의 PORT로 바꿀 수 있습니다. Upstash 주소·토큰을 둘 다 비우면 개발용 단일 프로세스 파일 저장소 `data/serverless-local.json`을 사용합니다. Vercel에서는 로컬 저장소로 대체하지 않으며 DB 미설정 오류를 표시합니다. 기존 초안의 `listening-rooms.json`과 32자리 링크는 새 6자리 방으로 자동 이전하지 않습니다.

## 사용 규칙

1. 방을 만들면 6자리 숫자 코드가 발급됩니다. 같은 사이트 첫 화면의 코드 입력 또는 초대 링크로 접속하고 닉네임을 등록합니다. 코드를 아는 사람은 참여할 수 있으므로 비공개 인증 방은 아닙니다.
2. 첫 곡은 신청과 동시에 현재 곡이 됩니다. 이후 신청곡은 대기열에 들어가며, 재생 종료 시 투표를 반영해 다음 곡으로 넘어갑니다. 빈 대기 상태에 다시 곡을 넣으면 즉시 시작합니다.
3. 방을 만든 브라우저에만 공식 YouTube 플레이어를 표시합니다. 다른 참여자는 현재 곡 확인·신청·투표에 참여합니다. 중앙 영상은 클릭할 수 없으며 아래 재생·일시정지 버튼으로 조작합니다. 자동 재생이 차단되면 재생 버튼을 누릅니다.
4. 방 생성자는 브라우저 쿠키로 식별하며 새로고침하거나 같은 브라우저로 재입장해도 재생 권한을 유지합니다. 생성자가 나가도 다른 참여자에게 재생 권한을 넘기지 않습니다. 방장의 실제 재생 위치를 저장하며, 버퍼링·일시정지·자동재생 차단 중에는 시간이 멈춥니다. 재생 확인이 10초간 끊기면 마지막 확인 위치에서 대기하고, 복귀 시 그 위치부터 이어 듣습니다. 일시정지 상태는 새로고침과 과반수 건너뛰기 후에도 유지하며, 다음 곡은 처음 위치에서 기다립니다. 재생 버튼을 누른 뒤 실제 재생이 확인되어야 방의 시간이 다시 진행됩니다. 장애 직전 확인되지 않은 몇 초가 반복될 수 있습니다. 같은 브라우저의 여러 탭 중 한 탭만 재생을 담당하며, 새로고침 후 기존 연결의 만료까지 최대 10초 대기할 수 있습니다.
5. 대기곡마다 듣고 싶어요(+1) 또는 이번엔 패스(−1) 중 한 표. 같은 버튼은 취소, 반대 버튼은 교체합니다. 신청 자체는 자동 찬성표를 만들지 않습니다. 순서는 항상 점수 내림차순이며 동점은 먼저 등록한 곡을 우선합니다. 동일 신청자의 연속 곡도 이 순서를 따릅니다. 현재 곡은 계속 재생하며 투표는 다음 곡부터 반영합니다.
6. 현재 곡은 현재 참여자 과반(`floor(N / 2) + 1`)의 건너뛰기 투표로 넘깁니다. 삭제·비공개(100), 외부 재생 금지(101·150) 오류만 자동으로 다음 곡으로 넘깁니다. 플레이어 오류(5), 잘못된 재생 요청(2), 연결 식별 문제(153), 알 수 없는 오류는 곡과 마지막 확인 위치를 유지하고 방장에게 재시도 버튼을 표시합니다. 재시도 시 플레이어를 새로 만들며 원래 일시정지 상태도 보존합니다. 플랫폼 정책으로 재생되지 않는 영상이 있을 수 있습니다.
7. 브라우저는 15초마다 접속 확인을 보내며, 진행 중인 모임에서 90초 동안 연결 확인이 없는 사람은 다른 참여자의 다음 상태 갱신 때 자동 퇴장됩니다. 진행 중인 방의 명시적인 마지막 퇴장은 방을 즉시 삭제합니다. 모두 창을 닫거나 연결이 끊기면 마지막 접속 확인·작업 후 90초에 Redis가 진행 중인 방 데이터를 만료시킵니다. 방장이 명시적으로 마친 모임은 종료 시각부터 24시간 보관하며 재생과 신규 참여·신청·투표를 차단합니다. 접속 조회만 하는 미참여자는 방 수명을 늘리지 않습니다. 브라우저 절전·OS 수면으로 접속 확인이 중단돼도 같은 규칙을 적용합니다.
8. HttpOnly 쿠키로 브라우저를 식별합니다. 새로고침·닉네임 변경·반복 요청으로 표를 늘릴 수 없습니다. 다른 브라우저·시크릿 모드·쿠키 삭제·여러 기기 사용까지 막는 실제 기기 인증은 아닙니다. 퇴장 시 해당 참여자의 표도 제거됩니다.
9. 합계와 본인의 선택만 표시합니다. 다른 사람의 개별 투표·브라우저 식별값은 반환하지 않습니다. 소규모 방에서는 합계 변화로 선택을 추측할 수 있어 완전한 익명성을 보장하지는 않습니다.

## 곡별 감상과 모임 요약

- 현재 곡 옆의 **감상** 또는 하단 **감상·기록**에서 입력합니다. 기존 레코드·참여자·신청·대기열 배치는 유지하며 입력과 요약은 모달로 표시합니다.
- 직접 들은 곡에 좋았어요·보통이에요·아쉬웠어요 중 하나를 남깁니다. 좋았어요를 선택하면 멜로디·소리, 가사, 추억, 분위기를 선택적으로 여러 개 고를 수 있습니다. 대기열 투표를 감상으로 변환하거나 미응답을 호감으로 간주하지 않습니다.
- 서버가 현재 곡·최근 재생 이력 30곡·이미 기록한 본인 곡인지 확인합니다. 아직 대기 중인 곡과 임의의 곡은 거절합니다. 실제 청취 여부는 자기 보고이며 플레이어 노출이나 투표만으로 감상을 자동 생성하지 않습니다.
- 감상은 방·브라우저·재생곡 ID별 하나이며 수정할 수 있습니다. 닉네임 변경과 같은 브라우저의 퇴장·재입장에도 중복 집계하지 않습니다. 한 사람이 한 모임에서 최대 200곡까지 기록하며, 재생 이력에서 빠져도 이미 남긴 감상과 곡 정보는 요약에 보존합니다.
- 개인 요약은 직접 평가한 곡 수·호감도별 수·좋았던 이유의 횟수를 표시합니다. 이유는 좋아한 곡만 집계하며 동률은 함께 표시합니다. 성격, MBTI, 고정된 취향 유형이나 인과 효과를 판정하지 않습니다.
- 모임 요약은 두 명 이상이 응답하고 응답자 모두 좋아한 곡, 좋았어요와 아쉬웠어요가 함께 나온 곡을 보여줍니다. 곡별 응답 인원을 표시하고 미응답자는 제외합니다. 다른 사람의 개별 감상·이유·식별값은 반환하지 않습니다. 소수 응답에서는 합계로 다른 응답을 추측할 수 있습니다.
- 퇴장하면 요약을 표시합니다. 방장은 **감상·기록 → 모임 마치고 요약 보기**에서 확인 후 전체 모임을 마칠 수 있습니다. 참여자의 다음 상태 조회 시 재생을 멈추고 각자의 요약을 자동으로 엽니다. 곡의 자연 종료나 빈 대기열은 전체 모임 종료로 간주하지 않습니다.
- 명시적으로 종료한 방은 종료 후 24시간 동안 기존 참여자만 감상을 보완할 수 있습니다. 읽기·접속 확인·감상 수정으로 보관 기한을 연장하지 않습니다. 기존의 진행 중인 빈 방 삭제 규칙은 유지합니다.
- 감상을 남긴 뒤의 요약과 종료·퇴장 시점의 요약은 브라우저 localStorage에 최근 20개 모임까지 저장합니다. 첫 화면 하단 **감상·기록**에서 다시 볼 수 있습니다. 다른 기기로 동기화하지 않으며 브라우저 데이터 삭제 시 사라집니다. 모임에 연결되어 있지 않으면 다른 사람의 이후 감상은 저장된 요약에 반영되지 않습니다. 브라우저 저장이 차단된 경우 저장 불가 안내를 표시합니다.

## 곡 신청 검증과 도배 방지

- 서버가 YouTube videos.list로 음악 카테고리(10), 공개 상태, 업로드 처리 완료, 외부 재생 허용 여부를 확인합니다. 실시간·예정 방송은 거절합니다. 검색과 직접 링크 모두 같은 검증을 거치며 제목·채널명·채널 ID는 YouTube 응답에서 가져옵니다.
- 음악 분류는 등록자가 지정한 카테고리이므로 음악만 포함한다고 보장하지 않습니다. 별도의 영상·채널 허용 목록은 사용하지 않으며, 방장은 대기열의 삭제 버튼으로 부적절한 곡을 제거할 수 있습니다. 현재 곡은 기존 과반 건너뛰기 규칙을 사용합니다.
- 같은 방·브라우저의 신청 시도는 30초에 한 번입니다. 외부 API 검증에 실패해도 30초 후 다시 시도합니다. Redis의 공유 제한으로 동시 요청과 퇴장 후 재입장에도 간격을 유지합니다.
- 개인 대기곡은 최대 3곡이며 현재 재생곡은 포함하지 않습니다. 재입장해도 같은 브라우저의 기존 대기곡을 합산합니다. 곡이 재생되거나 방장이 삭제하면 자리가 생깁니다. 다른 브라우저·쿠키 삭제까지 막는 본인 인증은 아닙니다.
- 방장만 대기곡을 삭제할 수 있으며 해당 곡의 투표도 함께 정리합니다. 재생 중인 곡·공유 재생 위치·다른 대기곡은 보존합니다.
- 검증에는 신청 시도당 videos.list 호출이 한 번 추가됩니다. API 키·할당량·연결 장애 시 검증을 생략하지 않으므로 신청할 수 없습니다. 지역·연령 등 실제 플레이어의 추가 제한은 재생 시 확인됩니다.

## 서버리스 저장 구조

- `api/index.js`: Vercel 함수 진입점. 재생·투표 규칙은 `lib/handler.js`, 대기열과 접속 정리는 `room.js`.
- `lib/storage.js`: Upstash REST 연결과 방 단위 원자적 비교 후 저장. 방 상태·투표를 읽은 이후 다른 요청이 먼저 저장했다면 최신 상태로 다시 처리합니다. 중복 곡 종료 요청으로 두 곡이 연속 건너뛰어지지 않도록 현재 곡 ID도 확인합니다.
- `lib/storage-local.js`: 로컬 개발·테스트 전용 저장소. 파일에 기록이 남아 있어도 만료된 방은 조회할 수 없습니다. 다음 쓰기 시 만료 데이터를 정리합니다.
- 진행 중인 방 데이터 TTL 90초, 종료한 방은 종료 시각부터 24시간, 검색 캐시 TTL 5분, 새 검색 제한 3초, 같은 방·브라우저의 신청 제한 30초. 방 만료는 Redis TTL로 처리하므로 Cron이나 계속 실행되는 서버가 필요 없습니다.
- `lib/reflections.js`에서 감상 검증·저장·개인 응답 분리·모임 합계를 처리하고, `public/reflections.js`에서 직접 응답의 요약과 브라우저 보관을 처리합니다. `public/listening-notes.js`는 감상 입력·기록 조회·모임 종료 모달을 관리합니다. API 응답에 다른 사람의 개인별 감상 저장소를 포함하지 않습니다.
- `playback.position`에 방장이 마지막으로 보고한 실제 위치, `reportedAt`에 서버 수신 시각을 저장합니다. 재생 상태 변경 즉시 및 약 3초마다 보고하며, 접속 확인과는 별개입니다. 재생 중에만 최대 10초 동안 화면 위치를 추정하고, 보고 만료 시 저장된 실제 위치로 돌아가 대기합니다. 방장 연결 확인 중·연결 끊김·버퍼링·일시정지·재생 시작 대기를 표시합니다. 기존 시간 기반 방 데이터는 저장된 일시정지 위치를 보존하며, 위치가 없는 재생 데이터는 현재 곡의 처음부터 재생 준비 상태로 전환합니다.
- 영상 길이만으로 곡을 전환하지 않습니다. 방장 플레이어의 자동 종료 보고와 실제 마지막 위치(끝에서 8초 이내)를 확인해 다음 곡을 시작하며, 사람의 승인은 필요 없습니다. 재생·일시정지 명령도 진행 보고와 같은 순서로 처리합니다. 곡 ID·재생 연결·연결 차수·보고 순서를 검사하여 지연·중복 보고와 다른 탭의 충돌을 차단합니다. 영상 길이는 플레이어 메타데이터를 사용합니다. 신청 시 음악 분류와 공개·외부 재생 여부 검증에는 Data API를 별도로 호출합니다. 과반수 건너뛰기와 재생 불가 영상의 다음 곡 전환은 유지합니다.
- YouTube 오류 분류와 API 로더는 `public/youtube.js`에서 공유합니다. API 로딩 실패·15초 시간 초과 시 실패한 스크립트·타이머·콜백·요청 캐시를 정리하므로 새로고침 없이 다시 시도할 수 있습니다. 플레이어 준비 완료가 15초간 오지 않는 경우에도 재시도 버튼을 제공합니다. 오류 상태에서는 자동 로딩을 반복하지 않으며, 오류 코드와 마지막 위치를 서버에 보관해 새로고침 후에도 명시적 재시도를 기다립니다. [공식 오류 코드](https://developers.google.com/youtube/iframe_api_reference#onError)를 기준으로 분류합니다.
- 고정 길이의 녹화된 영상·음악을 대상으로 합니다. 실시간 방송은 길이가 계속 바뀌므로 지원 대상이 아닙니다. 기기의 시각 차이는 서버 응답 시각과 브라우저의 단조 시계로 보정합니다.
- Vercel Production·Preview·로컬은 기본 키 접두사가 달라 같은 DB에서도 방과 검색 캐시가 분리됩니다. 다른 앱까지 같은 DB를 공유한다면 `REDIS_KEY_PREFIX`를 별도로 지정하세요.
- 상태 조회는 화면이 보일 때 각 기기에서 5초마다, 접속 확인은 별도로 15초마다 실행합니다. 곡 변경과 연결 상태 반영에는 조회 간격·네트워크 지연이 생깁니다. 조회에 따른 재생 연결 만료 저장은 기존 TTL을 유지하여 미참여자의 조회가 빈 방 수명을 늘리지 않게 합니다. Vercel·Upstash 모두 무료 플랜 기준으로 사용하며 요청량을 확인하세요. 대규모 운영에는 방 접근 제어와 생성 요청 제한이 추가로 필요합니다.

## 논문과의 연결

T10 최종 논문은 공개 집계자료 330명에서 외향성과 평균 음향적 긍정성의 뚜렷한 양의 관계를 확인하지 못했습니다(r=0.065518, 95% CI −0.045077~0.180637). 정서적 안정성–가사 긍정 정서의 예상한 양의 관계와 가사 결합에 따른 개방성 예측의 평균 성능 개선도 확인하지 못했습니다. 성격으로 취향을 짐작하기보다 실제 신청·투표를 반영하고, 들은 뒤 직접 남긴 감상과 이유로 이번 모임을 돌아보는 설계로 연결했습니다. 관계가 없다는 증명이나 앱 효과에 대한 검증 결과는 아닙니다.

이 앱은 **논문 데이터를 직접 활용한 앱이 아니라, 논문의 결과에서 착안한 앱**입니다. 논문에서 사용한 개인별 성격·청취 음악의 집계자료는 현재 모임에서 듣고 싶은 곡이나 참여자의 의견을 나타내는 데이터가 아니므로, 현재 앱의 실용적인 핵심 기능에 직접 적용할 적절한 방법을 찾지 못했습니다. 따라서 논문 원자료나 이를 대체한 예시 데이터를 곡 추천·대기열 정렬·재생 결정에 사용하지 않았습니다.

함께 들을 곡은 사용자의 신청과 투표로 정하고, 감상 요약은 사용자가 별도로 남긴 실제 평가만 집계합니다. 찬성 +1·패스 −1, 동점 시 신청순, 과반 건너뛰기와 감상 입력·집계 방식은 앱에서 정한 규칙이며 논문에서 도출하거나 검증한 규칙이 아닙니다. 논문은 공동 선곡·감상 기록의 효과를 검증하지 않았습니다. 논문 수치는 하단 연구 설명에서 출처와 배경을 알리는 용도로만 제공합니다.

카드 2의 BRB-C04(논문 결과의 수치·규칙·방법을 실제 기능에 사용)는 충족했다고 기록하지 않습니다. 현재 구현 범위는 연구 결과에서 착안한 공동 음악방입니다.
